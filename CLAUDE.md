# Mount Sheet Sync — памятка для Claude

Этот файл Claude Code читает сам, когда открывает папку репозитория. Здесь — что за проект, в каком он состоянии,
как в нём работать и что обязательно обновлять после каждой правки. Подробности — в `docs/reference/`.
Отвечать пользователю по-русски.

## Что это

Связка для фарма маунтов в World of Warcraft (Retail, Midnight 12.x):

- **Аддон** (корень репозитория = папка аддона, Lua 5.1): запоминает убийства боссов, персонажей, коллекцию
  маунтов и статистику убийств, показывает в игре «Осталось на этой неделе», строку попытки в чате, подсказку
  босса и значок в Атласе приключений. Публикуется на CurseForge (проект 1761349, `mount-sheet-sync`).
- **Программа в трее** (`program/`, C# 5 / .NET 4.8, без зависимостей, один exe): читает SavedVariables аддона,
  ведёт Google-таблицу пользователя (Sheets API, права `drive.file`), пишет аддону `SheetData.lua` (список
  «Осталось», попытки) и `Program.lua` («программа запущена»). Сама себе установщик и автообновление с GitHub.
- **Таблица** (Google Sheets): листы «Рейды», «Подземелья», «Мировые боссы», «Рейды <Имя>», «Сводка»; каталог
  маунтов — `program/catalog.json`.
- **Сайт**: репозиторий `Zlodyaga/zlodyaga.github.io` → https://zlodyaga.github.io/ (кнопка скачивания exe,
  политика конфиденциальности, политика подписи кода).
- Код: `Zlodyaga/mount-sheet-sync`, ветка `main`. Лицензия MIT.

## Как работать

- Шрифты WoW (минимум русский клиент) не рисуют «·» и стрелки «→ ← ↑ ↓» — вместо них квадратик. В текстах аддона —
  «-» и «>»; «—», ««»», «…» и буквы с диакритикой работают. Проверяет `test_locale.py`.
- Аддон: Lua 5.1 для WoW. «Секретные» значения (`issecretvalue`) не сравнивать и не печатать; в 12.x
  `C_Timer.After` — только с функцией. Подсказки и сканы — дёшево: горячие места замерены в `addon.md`.
- Программа: C# 5 (без `?.`, `$""`, `nameof`), .NET 4.8, без NuGet; сборка `program\build.cmd` (компилятор из
  Windows). Тексты интерфейса и журнала — через `Tr._ / Tr.F / Tr.L`, переводы в `tools/i18n/ui*.txt`, `log.txt`
  → `python3 tools/i18n/build.py`. Русские слова таблицы — `tools/i18n/sheet_words.txt` → `build_sheet.py`.
- Концы строк сохранять как в файле (`.gitattributes`: `* -text`): часть файлов аддона CRLF (Collection.lua,
  Tooltip.lua, toc, Statistics.lua…), часть LF. Правя файл, не превращать CRLF в LF и наоборот.
- `Statistics.lua` не править руками — генерирует `python3 tools/catalog/statistic_ids.py --write`. `Entrances.lua` — тоже:
  `python3 tools/catalog/entrances.py --write` (таблицы игры с wago.tools; там же точки раров из колонки «Точка»); после новых мест и раров в каталоге — перезапустить.
  Точки, которые показала сама игра, — `tools/catalog/entrances_game.json` (их собирает аддон-сборщик `tools/probe/MountSheetSyncProbe`,
  файл делает `entrances_from_probe.py <его SavedVariables>`); они важнее таблиц.
- `SheetData.lua` и `Program.lua` в репозитории — пустые (`= nil`); их пишет программа у пользователя.
- Тесты: `bash tools/run_tests.sh` (или `--no-ui`) — нужны Linux, mono, python3 + lupa, node, Xvfb и т. п.
  (на Windows — WSL; иначе полагаться на CI `ci.yml`: на push в `main`, PR и Run workflow, ~4 мин). На ПК
  пользователя есть Python + lupa: тесты аддона идут локально (`python tools/tests/test_addon2.py`, что идёт и
  что нет — в testing.md); `gh` есть (с 07.11.2026, вход Zlodyaga; если его нет в PATH — `C:\Program Files\GitHub CLI\gh.exe`). Тесты переписывают
  `tools/tests/sv_collection.lua` и `status_left.json` (метки времени) — перед коммитом вернуть
  `git checkout`, кроме случая, когда менялось содержимое (тогда закоммитить новые). В e2e индексы колонок
  заданы жёстко — при новых колонках сдвинуть.
- Номер версии стоит в нескольких местах — таблица в `docs/reference/release.md`. Новой возможности нужна
  свежая другая половина — поднять `Program.MinAddon` или `MIN_PROGRAM` в `MountSheetSync.lua`.

7. Никаких секретов в файлах: ключей, токенов, client secret, паролей, личной почты.

## Выпуск — только когда пользователь попросил

GitHub → Actions → **Release** → Run workflow (или
`gh api -X POST repos/Zlodyaga/mount-sheet-sync/actions/workflows/release.yml/dispatches -f ref=main
-f 'inputs[what]=program|addon|both' -f 'inputs[kind]=release|alpha|beta'`), перед этим — зелёный CI на этом
коммите и поднятая версия той части, что выходит. Программа → тег `v<версия>` и выпуск GitHub (exe + архив);
аддон → тег `addon-v<версия>`, только CurseForge. Аддон не выпускать через «Releases → Draft a new release».
После — проверить `releases/latest` и файл на CurseForge.

## Правила работы с пользователем

- Пароли, коды, ключи и токены вводит он сам (CF_API_KEY, SignPath — в секретах GitHub). Не входить в аккаунты
  за него; сайты, где нужен вход, — в его браузере Chrome, где он уже вошёл.
- Не принимать соглашения и условия за него; письма — только черновиком или с его «да»; публиковать и менять
  публичное (сайт, CurseForge, выпуски) — только с его согласия.
- Удалять его файлы и таблицы — только после его ответа.
- Токены у пользователя ограничены: проверять скриптами, а не читать большие файлы целиком; отчёт — коротко.
