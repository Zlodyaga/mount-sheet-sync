# Тесты

`bash tools/run_tests.sh` (или `--no-ui` без Xvfb) — всё; временные файлы в `$MSS_TEST_TMP`. Перед тестами
собираются тестовый exe (`tools/build_test_exe.sh`, `-define:TESTS`) и хосты `tools/cs_host/*.exe`, проверяются
переводы (`tools/i18n/build.py --check`, `build_sheet.py --check`) и список статистик (`tools/catalog/statistic_ids.py`:
колонка каталога и `Statistics.lua` совпадают с ним). Нужны mono, python3 + lupa, node, Xvfb,
xdotool, stalonetray, imagemagick. В CI — то же (`.github/workflows/ci.yml`).

ScrollBox в `wow_mock.lua` упрощён: `SetDataProvider` вызывает инициализатор для каждой строки (в игре — только для
видимых) на кадрах из `box._pool`; `box._inits` считает вызовы, `box._view._extent` отличает список (16) от
персонажей (20). Строки списка в тестах читаются из `_pool`, а не по координатам FontString.

Особенности: тесты переписывают `tools/tests/sv_collection.lua` и `status_left.json` (метки времени) — перед
коммитом вернуть (`git checkout`), версию в `status_left.json` оставлять актуальной. Под mono нет общих между
процессами именованных мьютексов и ярлыков «Пуск» — тесты это учитывают. Индексы колонок в e2e жёстко заданы:
при новых колонках таблицы их надо сдвинуть.

На Windows (Python + lupa, без mono): `paths.py` ставит локаль `C` — иначе Lua `string.lower` по системной cp1251
портит кириллицу в UTF-8 (в игре локаль `C`). Идут `test_addon2`, `test_minimap`, `test_offline`, `test_locale`,
`test_collection`; `test_attempts`, `test_collection_sync` и другие без `mono` в пути — с хостами, собранными `csc`, и заменой `mono.exe`, которая запускает exe напрямую; `test_addon_left` — с готовым `SheetData.lua` первым аргументом (Node-скрипт таблицы под Windows
не работает; дата списка тогда старая — одна проверка «сегодня в» не проходит). `test_attempts_addon` — только в CI.
`test_addon_left.py` (3.0.6): имитация `MapzerothAddon` — путь отдан ему, не нашёл пути — метка игры, галочка снята — не
трогаем, нет Mapzeroth и цель на другом континенте — одна подсказка; `test_locale.py` — галочка «Путь через Mapzeroth».
`test_local_book.py` (2.10.1): дневные копии — одна за день, хранятся 7; (2.10.2) возврат из копии: нынешние данные остаются рядом, пустая копия не берётся; статистика: что входит в сообщение, нет имён, вилка персонажей (сама отправка не проверяется). `e2e_local.py`: с `autoAddCharacters = false` новый персонаж не добавляется.
`e2e_lang.py` проверяет и то, что немецкая таблица получает советы раров по-немецки (`contentL10n`, 2.10.1).
e2e (`e2e_google`, `e2e_chars` и др.) на Windows тоже идут (проверено 10.11.2026, exe из `csc` и замена `mono.exe`): вывод программы читает `paths.out_text` — exe без консоли пишет в кодировке ANSI (cp1251), под mono — UTF-8; имитации запускаются тем же Python (`sys.executable`: `python3` на Windows бывает запускалкой, и `terminate()` гасил только её, а имитация оставалась на порту); `allow_reuse_address` на Windows выключен — занятый порт сразу даёт ошибку, а не ответы старой имитации. `ConnectionResetError` в выводе имитации на Windows — обрыв соединения клиентом, не ошибка.

## Скриншоты окон аддона

`test_addon_left.py` выгружает разметку окна (кадры, размеры, якоря, цвета, шрифты, текстуры) в `tools/layout_left.json`,
`layout_all.json`, `layout_attempts.json`, `layout_log.json`, `layout_settings.json`; `python tools/screens/render.py` рисует их в браузере
(playwright, Chromium) в `docs/screens/addon-*.png`: шрифты и текстуры — настоящие из `Media`, порядок слоёв и кадров как в игре,
слой HIGHLIGHT не рисуется. Персонажи — вымышленные из `wb_left.json`, классы — из `MountSheetSyncDB.chars` в тесте. На время
выгрузки тест ставит обычную неделю: программа запущена, таблица сброшена. Значки маунтов — заглушки с первой буквой названия.
Новая картинка на CurseForge получает новый адрес: его надо подставить в `docs/curseforge-description.md` и на сайте.

Перед выпуском — ручная проверка в игре по списку `docs/ingame-check.md` (что нажать и что должно появиться; для аддона 3.0.5 и программы 2.10.1).
