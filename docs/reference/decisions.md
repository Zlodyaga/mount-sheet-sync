# Решения и ограничения

Коротко: что решили и почему, чтобы не обсуждать заново.

- **Программа на C# 5 / .NET 4.8 без зависимостей** — компилятор есть в каждой Windows, исходники рядом с exe,
  любой может собрать сам (`build.cmd`).
- **Таблица программы через Google (drive.file) — основной режим**, скрипт Code.gs (как в 1.x) — запасной.
  Права `drive.file` не чувствительные: без проверки Google, без лимита 100 пользователей, без экрана
  «приложение не проверено». Скрипт-режим масштабируется без общей квоты, но ставится сложнее (копия, развёртывание,
  предупреждение Google для своего скрипта) и не умеет новое с 2.x. Идея на будущее, если квоты не хватит:
  шаблон таблицы со скриптом-посредником (только чтение/запись ячеек), а логика остаётся в программе.
- **Квота 300 чтений/мин на проект.** С 2.9.2 — 3 чтения на отправку убийств со списком (было 6): таблица загружается
  один раз на проход цикла. Метаданные не кешируем между проходами: в них `lastWeekReset` и версия вида, устаревшие
  привели бы к лишнему сбросу. Список читает только обычные ячейки, поэтому таблица из памяти после записи ему подходит.
  Дальше по порядку: попросить увеличение квоты (бесплатно), включить оповещение о 80 % квоты, при росте —
  скрипт-посредник. Делить пользователей по нескольким проектам Google не будем (похоже на обход правил).
- **«Осталось» по расписанию — только пока запущена игра** (2.8) — меньше запросов.
- **«Сброс недели» делает программа сама** (2.9.2). Кнопку забывали, и список врал; нового смысла у сброса нет — те же
  действия, что после кнопки, включая повторную отметку убийств этой недели. Настройки «выключить» нет: сброс недели игры
  не зависит от желания игрока, а ручные «Да» в таблице кнопка стирала так же. Кнопка осталась (программа не запущена, повтор).
- **Рары — без колонок персонажей** (2.9.2). Откат у каждого рара свой и короче недели: галочки пришлось бы чистить по
  разным расписаниям, а дату на персонажа — добавлять при каждом новом персонаже. У аддона уже есть время и персонаж каждого
  убийства (журнал 21 день), поэтому считает он. Цена: убийства на другом аккаунте игры он не видит. Запись из игры остаётся
  `kind = world`, откат берётся из «Сброс / частота». Кнопка «Сброс недели» ушла в настройки: её делает программа.
- **Рар без статистики**: у Исхака и других раров нет статистики убийств, поэтому убийства до установки аддона не
  подтягиваются — «Попыток» начинается с 0. Счёт идёт с добычи. Настоящие данные 31.10.2026: запись `D-…` дошла, попытка
  засчитана; потерять её можно было только при смене цели перед добычей — с 3.0.3 имя запоминается заранее.
- **Окно 3.0: персонажи слева, списки на ScrollBox.** У игроков бывает 20+ персонажей: прежнее окно делало по
  FontString и кнопке на каждую строку (сотни кадров при открытии), ScrollBox делает кадры только для видимых строк
  и переиспользует их. Списки пересобираются по ключу данных, а не на каждый `Refresh`. Данные других персонажей —
  те же `chars[]` из `SheetData.lua` (программу менять не пришлось); «Не фармлю» — только для текущего персонажа
  (запись `P-…` пишется от его имени). «Не писать в чат» и «Очистить журнал» ушли в настройки: ими пользуются
  редко, а место внизу окна нужно частым действиям. Мажорная версия — потому что окно другое целиком.
- **Локальная модель (gpt-oss:20b) для кода аддона не годится** (проверено на 3.0, 30.10.2026): готовый фрагмент
  вставляет с правками или по нескольку раз, теряет кавычки. Справилась только с маленькой функцией по описанию
  (`ns.GetAttemptsList`), и ту пришлось переделать ради скорости. Большие правки окна — не ей.
- **Счётчик попыток — в таблице**, общий на всех персонажей; аддон досчитывает неотправленное сам. Повторы после
  «Сброса недели» помечаются `again` и не считаются.
- **Оформление ячеек готовой таблицы — `updateCells` по ячейкам, не `repeatCell`**: repeatCell пропускает строки,
  скрытые фильтром листа (проверено на настоящей таблице 28.10.2026). Новая таблица оформляется до фильтра — там
  всё равно.
- **История попыток — из статистики игры** (2.9, как у Rarity): игра хранит убийства боссов по персонажам. Берём
  max(ячейка, сумма) — без двойного счёта и без отката ручных правок. Список статистик — свой, из данных игры
  (wago.tools, таблица Achievement), сверен с Rarity по совпадающим; Rarity (GPL) не копируем. Статистику со
  «всеми сложностями» для маунта одной сложности не берём — лучше недосчитать, чем приписать лишнее.
- **Убийство узнаётся по номеру боя** (аддон 3.0.2, программа 2.9.1): Blizzard пишет имена по-разному (бой 1563 —
  «Галеон», в Атласе/каталоге было «Галлеон»), имя — запасной путь.
- **Без «·» и стрелок в текстах аддона** (3.0.1): русский клиент рисует их квадратиком (30.10.2026). Разделитель — «-»,
  стрелка — «>»; `test_locale.py` не пускает их обратно.
- **Подсказка юнита — только у раров** (3.0): в рейдах и подземельях игра прячет имена НИП даже до боя, и юнит из
  подсказки не получить — у боссов подсказка не работала; боссы — только значок в Атласе приключений.
- **Рары считаем по добыче**: у них нет ENCOUNTER_END/BOSS_KILL и сохранений, поэтому попытка — открытая
  добыча с трупа (как у Rarity). Нужен список из таблицы программы 2.8+: без него аддон не знает, какие рары важны.
- **Без телеметрии и своих серверов.** Программа говорит только с Google и (раз в сутки) с GitHub API.
  «Сведения для отчёта об ошибке» — текст, который пользователь копирует сам, без имён и таблицы.
- **Подсказки об установке программы** в аддоне — только в пустой «Осталось» и в `/mss left` (правила Blizzard и
  CurseForge, без спама).
- **Ссылки на скачивание** — только сайт (правило CurseForge). Сайт отдаёт exe напрямую: программа сама себе
  установщик, аддон — из CurseForge или из полного архива GitHub.
- **Программа и аддон выходят отдельно** (с 2.8.0): правка программы не тащит «новый» аддон в CurseForge и
  наоборот. Цена — у пользователя могут разойтись версии; на это `MinAddon` / `MIN_PROGRAM` и мягкие подсказки.
  Выпуск — кнопкой в Actions, а не через Releases (иначе у аддона появлялся бы выпуск GitHub без exe).
- **Пробные версии** — теги `-alphaN`/`-betaN`: пре-релиз, на них обновляются только желающие.
- **Логотип в бренде Google убран** — с ним требовалось подтверждение бренда, а сайт на `github.io` Google не
  признаёт «своим доменом». Ответ Google 27.10.2026: страница и политика должны быть на своём подтверждённом домене.
  Тратить деньги на домен не стали: логотип убран окончательно (27.10.2026), Google попросили закрыть заявку.
  Захочется логотип — домен (~$10–15/год, или бесплатный `*.eu.org` без гарантии), перенос сайта, ответ на письмо.
- **exe без подписи** — SignPath Foundation (бесплатная подпись для open source) отказал 27.10.2026: проект пока
  мал. Шаги подписи в release.yml оставлены на будущее (заявку можно подать снова, когда будет больше
  пользователей и звёзд); платный сертификат не покупаем.
- **Безопасность при работе с пользователем**: пароли, ключи и токены вводит он сам (CF_API_KEY, SignPath — в
  секретах GitHub); выпуски и теги создаёт он; соглашения на сайтах не принимаем за него.
- **Окно 1060×600, таблицы вместо строк-предложений** (аддон 3.0.3): числа в одном столбце сравниваются взглядом, длинное название больше не обрезает попытки и шанс. На 1920×1080 при стандартном масштабе экран — около 1365×768 единиц, так что окно занимает 78 % по обеим сторонам; шире не пошли. По каталогу при ~6 единицах на букву целиком влезает 90–95 % маунтов и 80–85 % боссов; остальное — в подсказке. Прокрутка столбцов сетки — сдвигом на персонажа, а не кадром с обрезкой: кадров строк столько же, данные не перестраиваются.
- **Сетка всех персонажей — и с прокруткой, и без** (аддон 3.0.3): по умолчанию широкие столбцы с прокруткой (выбор пользователя), «все столбцы сразу» — в настройках для 15+ персонажей.
- **Раздельные сохранения — только у строк `Normal/Heroic/Mythic`** (программа 2.9.2, аддон 3.0.3): все такие строки каталога — рейды Legion и новее, где у каждой сложности своё сохранение. В рейдах Cataclysm и MoP (`Normal/Heroic`) сохранение считаем общим, подземелья не трогаем. Строку не дробим и «Да» не меняем по смыслу: убитые сложности лежат в скрытой колонке `N/H/M`, поэтому формулы и «Сводка» работают как раньше.
- **Своё оформление окон вместо шаблонов Blizzard** (аддон 3.0.3): в игре окно выглядело тусклее согласованного макета из-за мраморного фона, кнопок и шрифта игры. Страницу браузера в WoW показать нельзя, но кадры, текстуры и шрифты могут быть своими. Цена — окно не похоже на родное, внешний вид поддерживаем сами, аддон вырос примерно на 1 МБ (в архиве вдвое меньше).
- **Шрифты лежат без изменений**: у PT Sans в лицензии (SIL OFL) зарезервированное имя, изменённую копию (например, только с нужными буквами) пришлось бы переименовывать. Лицензии — `Media/OFL-*.txt`. Шрифты из Google Fonts: `ofl/ptsans`, `ofl/philosopher`.
- **ID маунта мировых боссов — из каталога**: на листе «Мировые боссы» скрытой колонки нет, добавлять её ради значка незачем (колонки персонажей идут сразу за «Источником»); `StatusMounts` находит ID через `MountIndex`, если колонки нет.
- **Картинки окна для README и CurseForge рисуем сами** (`tools/screens/render.py`), а не снимаем в игре: на снимке были бы настоящие имена и сервер игрока. Имена вымышленные, значки маунтов — заглушки, чтобы не хранить арт Blizzard.
- **Данные на этом компьютере — та же «таблица» в файле, а не своя модель** (2.10.0). `LocalBook` реализует `IStructuredBook`, поэтому `SheetLogic`, `CollectionSync` и `SheetUpgrade` остаются общими. Листы создают те же запросы `SheetBuilder`: `LocalBook.Run` берёт из них значения, а оформление пропускает, поэтому новые колонки каталога появляются сами. Формулы не считаем: логика их значения не читает, ячейка остаётся пустой и помечена в `formulas`.
- **В `LocalBook.Apply` запросы не выполняются:** значения обновления вида правит сам `SheetUpgrade` (`memory`). В Google копия в памяти после `Apply` выбрасывается, а здесь она и есть данные, поэтому новый вид таблицы обязан полностью описывать правки значений в `memory`.
- **Google и локальные данные не синхронизируются.** Это два отдельных места, каждое со своим списком отправленного: `--import-local` копирует список, чтобы убийства не считались дважды, а вернувшись в Google через `--storage google`, программа дошлёт туда записи, которых там ещё нет. Так меньше риска, чем при двусторонней синхронизации.
- **Новые игроки начинают без Google** (2.10.0): вход через Google и предупреждение «приложение не проверено» отпугивают, а квота 300 чтений/мин общая на проект. Нынешние игроки остаются на Google: `mode` у них сохранён, а настройки с таблицей и без `mode` считаются Google. Таблица — необязательный режим с советами по фарму и ручной правкой.
- **Слово «таблица» — только у тех, у кого она есть** (аддон 3.0.4, программа 2.10.0): аддон узнаёт это из `Program.lua` (`storage`), тексты без таблицы лежат отдельным набором, поэтому у нынешних игроков ни одна строка не меняется. В окне и настройках «таблица всех персонажей» остаётся: это таблица на экране.
- **Без Google персонажи добавляются сами** (программа 2.10.0): там нет таблицы, которую человек ведёт сам, а ручной шаг для каждого твинка только мешает. Новый персонаж добавляется до отправки его убийств: запись без листа считается отправленной, и отметка пропала бы. Снятые галочками запоминаются в файле данных, а не в настройках: они переезжают вместе с данными. Порога по уровню нет: его пришлось бы угадывать, а лишнего убирает одна галочка.
- **Данные каталога в аддоне — отложено, не отвергнуто** (05.11.2026): пока без программы аддон остаётся журналом. Часть данных можно будет положить в аддон, но это надо отдельно продумать: какие данные, размер, что не дублировать на Lua.
- **Названия — на языке аддона, а не таблицы** (аддон 3.0.4, программа 2.10.0): игра отдаёт названия только на своём языке, поэтому для другого языка переводы присылает программа из каталога (русский и английский), остальные языки получают английские. Таблица не меняется, переводится только показ: записи и сопоставление убийств идут по исходным названиям.
- **Переход с Google на компьютер предлагает перенос** (программа 2.10.0): «Сохранить» с выбранным «На этом компьютере» при готовой таблице спрашивает, перенести ли её; иначе данные начинались заново, и «Не фармлю» терялось — аддон хранит его только до следующего списка. Перенос поверх уже созданных данных откладывает их в `local-data.before-import.json`, а список отправленного берётся от таблицы, поэтому отмеченное только на компьютере отмечается в копии заново.
- **Окно — на целых пикселях** (аддон 3.0.4): при открытии и после перетаскивания окно ставится на целый пиксель экрана (`SnapToPixels`), а текст на красной кнопке и строка «Офлайн» — с тенью: иначе буквы мутные. Декоративный Philosopher убран совсем: у него тонкие штрихи («К», «т») в игре мылились. Кнопки и вкладки — PT Sans Bold 14, заголовки — PT Sans Bold 15 с тенью. Мелкий шрифт — 12 px вместо 11. Масштаб интерфейса не меняем: это настройка игрока.
- **Вход внутри другой зоны — в два шага** (аддон 3.0.4): игра показывает вход в «Душу Дракона» только на карте Пещер Времени, и вести к нему издалека она не может. Поэтому Ctrl + щелчок ставит метку у Пещер Времени на карте Танариса, а когда игрок в них вошёл, аддон сам переключает путь на вход — один щелчок вместо меню (решение пользователя). Свою цель игрока аддон не перехватывает. У Пещер Времени две карты с одним именем: игрок на любой из них уже внутри, иначе путь уводил его обратно к входу в пещеру. Ссылки на карту Пещер в `UiMapLink` нет, а запасной расчёт ставил первую метку над самим рейдом (он глубоко под землёй, z -220), поэтому точка входа в пещеру задана явно: `WaypointSafeLocs` 7655.
- **Вернул персонажа — вернулись его отметки этой недели** (программа 2.10.0): новые листы пустые, а записи уже числятся отправленными, и аддон навсегда показывал бы «убит, ждёт обновления». Повтор — тем же `again`, что и после сброса недели, поэтому попытки не удваиваются.
- **Названия на всех языках — из таблиц игры** (программа 2.10.0): игра отдаёт названия только на языке клиента, поэтому немецкие, французские, испанские и португальские берём один раз из выгрузки её таблиц (wago.tools: Mount, JournalEncounter, JournalInstance, Achievement) скриптом `tools/catalog/game_names.py`, по ID из каталога. Достижение для награды — по русскому названию или тексту награды, несовпавшие — вручную (`MANUAL`).
- **Достижения — своей вкладкой** (аддон 3.0.4, решение пользователя): их не убить за неделю, попыток у них нет, а в «Осталось» они только мешали. На вкладке — полное название, условие из игры и получено ли; щелчок открывает само достижение.
- **Вкладка «Достижения» — из всей таблицы, а не из «Осталось»** (программа 2.10.0): у рейдовых «Слав» сброс «Разово», и недельный список их не содержит. Программа шлёт все строки-награды отдельным `rewards`; четыре таблицы (рейды, подземелья, Mythic+, другое) — по просьбе пользователя.
- **На вкладке «Достижения» — только то, что можно получить сейчас** (программа 2.10.0, просьба пользователя): строки со «Статус» «Недоступен» (испытания Пандарии и Дренора, старые «Герой своего времени», «Дань бессмертию») не показываются. Достижения прошлых сезонов Mythic+ не получить, их маунты покупают за «Затерянное во времени седло»; седло дают за нынешний сезон, и его порог меняется (3400 в первом сезоне Midnight, 3600 во втором), поэтому условие берётся из самой игры — из новейшего достижения, где седло в награде (`game_names.py` → `saddle`), а не из каталога.
- **Запасные точки входов** (аддон 3.0.4): `GetDungeonEntrancesForMap` не вернул Вольную Гавань, «Операцию "Мехагон"», «Возвращение в Каражан» и черный ход Стратхольма (проверено `/mss route` у персонажа Орды, который там не был; значка нет и на карте Мехагона). У Краулока в журнале `UiMapID` 0, поэтому `GetEncountersOnMap` его не даёт. Координаты лежат прямо в `UI.lua`: четыре входа и один босс, каталог ради них не расширяем. Откуда: `JournalInstanceEntrance`, для черного хода `AreaTrigger` 6344 (в таблице входов у него точка главных ворот), для Мехагона — гайд (записи в таблицах нет), для Краулока — Warcraft Wiki.
- **Названия вне журнала игры** (программа 2.10.0): рары и сундуки — официальные имена из подсказок Wowhead, записаны в `NAMED` в `game_names.py` (в таблицах DB2 этих существ нет); зоны — `UiMap`; строки-описания («Любой босс…», «Обычные NPC…») переведены вручную. Место у наградных строк не переводим: в окне оно не показывается. Условия достижений добавляют в `SheetData.lua` около 30 КБ, это приемлемо.
- **Запасная точка входа у каждого рейда и подземелья каталога** (аддон 3.0.5): игра отдаёт значок входа не всем персонажам, поэтому точки берутся заранее из таблиц игры (`tools/catalog/entrances.py` → `Entrances.lua`), а не набираются по одной после жалоб. Вход — `JournalInstanceEntrance`, иначе значок карты `AreaPOI` (`PoiDataType` 1, `PoiData` — номер в журнале): у мест Midnight, Манагорна Омега и у входов на фазовых копиях континента (Цитадель Адского Пламени, Ни'алота) есть только он. Зона — по цепочке областей (`AreaTable.ParentAreaID`), а не самая маленькая из подходящих: прямоугольники зон перекрываются, и Зул'Гуруб попадал на край Выжженных земель. Вход в своей области внутри зоны — на карту с названием этой области («Душа Дракона» — Пещеры Времени, как показывает игра; подвалы Каражана не подходят). Вручную: Мехагон (записи нет) и черный ход Стратхольма (в таблице входов у него главные ворота). Мировые боссы — по-прежнему `KNOWN_BOSS_SPOTS`.
- **Рары каталога — из базы Rarity** (программа 2.10.1, каталог `2026-11-10`): 63 маунта с раров открытого мира. Номера существ, шанс, квест-откат и точка — из `DB/Mounts/*.lua` аддона Rarity (последний коммит 28.03.2026), маунты — таблица `Mount`, имена раров на шести языках — подсказки Wowhead (`tools/catalog/rare_names.json`), зоны раров без точки — карта НИП на Wowhead. Откат «Ежедневно» (у Rarity — дневные квесты; где квеста нет — то же, что программа берёт по умолчанию), кроме строк с несколькими рарами. Танаан: добыча с каждого из четырёх раров — раз в день (статья поддержки Blizzard 11514), маунт падает с любого — «Без отката». Не взяты: Глубинный звездный аурелид (Хирукона призывают приманкой раз в неделю, у положившего её — 100 %: в таблицу «100 %»), Верный обжора (цепочка заданий на 7 дней, не добыча), фарм обычных мобов с шансом около 1/3000 (своя таблица, см. TODO). Точка — в «Совете по фарму»: Ctrl + щелчок для раров пока не сделан.
- **Рар по номеру существа** (программа 2.10.1, аддон 3.0.5): у трёх завоевателей Зандалари одно имя и разные ящеры, а «любой редкий монстр зоны» в Midnight — 13–16 имён. Каталог хранит номера НИП (колонка «ID существ», на лист не пишется), программа отдаёт их в `npcs`, аддон сначала ищет строку по номеру из GUID и пишет в журнал название строки («Зандаларский завоеватель №2», «Любой редкий монстр: Харандар») — так программа находит строку прежним сравнением имён. Повтор (15 минут) у таких строк — по тому же номеру, а не имени. Нужна свежая другая половина: `Program.MinAddon` = 3.0.5.
- **Новые строки каталога в готовую таблицу — шагом вида таблицы** (layout 6, 2.10.1): лист рар строится из каталога один раз, поэтому новые рары приходят обновлением вида, а не при каждой загрузке. Дописанные строки получают свою полосу (`addBanding`): старую без её ID не расширить. Шанс на листе рар — с десятыми: у рар бывает 0,3–0,5 %, «0%» читалось бы как «не падает».
